# Changelog


<a id="org648c2b1"></a>

## 0.5.0


<a id="org3f264b0"></a>

### Added

-   `--preprocess-only` generates the preprocessed file without invoking TeX.
-   `--no-clobber` refuses to overwrite any existing preprocessed output file.
-   Generated output starts with an identifying TeX comment.


<a id="org85d4411"></a>

### Changed

-   Existing output is overwritten only when its first line is the erbtex generated-file marker. Otherwise erbtex warns and exits unsuccessfully before executing the template or invoking TeX. Output from earlier versions has no marker and must be inspected before moving, deleting, or marking it for subsequent overwrites.
-   Output is rendered before writing and replaced atomically through a temporary file beside the destination. Failed rendering preserves existing output.
-   Library methods return exit status codes or raise exceptions instead of terminating the calling process. The executable handles process exits.
-   Template syntax errors and runtime backtraces identify the input filename.


<a id="org953170b"></a>

### Fixed

-   TeX invocation preserves argument boundaries, repeated spaces, empty arguments, and literal shell characters without shell interpretation.
-   Input filenames precede trailing TeX commands, and fileless TeX invocations work.
-   `--invoke=` accepts complete executable names and paths, including spaces and hyphens, and rejects an empty executable name.
-   `--help` and `--version` match exactly and exit successfully after printing.
-   TeX failure exit codes propagate to the executable's caller.
-   Running erbtex without arguments prints usage instead of raising an error.


<a id="orgc5f25f9"></a>

### Documentation

-   Documented preprocessing options, overwrite protection, and handling of output generated by older versions.
-   Documented that files referenced by `\input` and `\include` are not preprocessed automatically, with a `--preprocess-only` workaround.
